# Trading Bot

Trading Bot is a TypeScript + Python trading research workspace. It is built around one asset catalog, one candle store, one folder per strategy, one shared backtest engine, and one Next.js dashboard for reviewing strategy stats, live alerts, and per-trade charts.

Most strategies in this repo were created by describing the trading idea to an AI coding agent, then having the agent implement the strategy inside this existing engine. This README is written for that exact workflow: a friend can pull the repo, read this file, describe a strategy to Codex, Claude Code, or another coding agent, and have the agent place the code in the correct files.

This project is for research and automation tooling. It is not financial advice.

## Quick Start

Requirements:

- Node.js 22
- Python 3.11
- Git
- Optional: Firebase credentials in `.env.local` if you need to pull/sync remote candles, backtest CSVs, or app state

Install and run:

```powershell
git clone <repo-url>
cd tradingBot
npm ci
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
npm run dev
```

Open the local Next.js URL printed by `npm run dev`, usually `http://localhost:3000`.

If the dashboard is missing market data or backtest files, ask the repo owner for the Firebase-enabled `.env.local`, then pull the needed files from Firebase with the scripts described below.

## High-Level Architecture

The flow is:

1. `config/assets.json` defines symbols, markets, tick sizes, unit labels, data files, and provider symbols.
2. `data/15m/*.csv` is the base candle store.
3. `python backtest-engine/runner.py prepare-data` rebuilds higher timeframe folders from 15m candles.
4. Each `strategy/<strategy-id>/` folder stores a TypeScript strategy definition, metadata, and generated `backtest_trades.csv`.
5. The Python backtest engine reads strategy metadata and TypeScript-compatible runtime settings, then writes trade CSVs.
6. The Next.js dashboard reads the strategy definitions and backtest CSVs through `src/lib/backtest.ts`.
7. Live signal checks use the same registered strategy definitions through `src/lib/live-signals.ts`.
8. Per-trade charts use `src/app/api/trade-chart/route.ts` and `src/components/trades/trade-price-chart.tsx`.

The important design idea: strategy metadata, backtests, dashboard stats, live signals, and trade visuals should all describe the same strategy. Do not make a one-off script that bypasses this flow unless it is only exploratory research.

## The Files an AI Agent Should Edit

When adding a new strategy, tell the AI agent to work in these files and avoid inventing a parallel system:

1. `strategy/<new-strategy-id>/strategy.ts`

   This is the strategy registration file. It should call `createStrategyDefinition(...)` and point to an evaluator in `src/lib/strategy-runtime/`.

2. `strategy/<new-strategy-id>/parameters/backtest.json`

   Use this for normal hand-coded or fixed-parameter strategies.

3. `strategy/<new-strategy-id>/machine_learning/selection.json`

   Use this for Bayes/logit/stump/echo-neural style strategies where the selected settings came from a training process.

4. `src/lib/strategy-runtime/<family>.ts`

   Put reusable strategy logic here. If the idea is a variation of an existing family, reuse or extend the closest existing evaluator.

5. `src/lib/strategy-loader.ts`

   Import the new `strategy.ts` file and append it to `STRATEGY_DEFINITIONS`. If this step is missed, the dashboard and live signal system will not see the strategy.

6. `src/components/trades/trade-price-chart.tsx`

   Add per-trade structure visuals here when the strategy needs custom chart overlays in the trade modal.

7. `config/assets.json`

   Edit this only if the strategy needs a new asset. Do not hardcode tick size, symbol, or dollar-per-unit values inside a strategy.

## Strategy Folder Pattern

A normal strategy folder looks like this:

```text
strategy/my_new_strategy/
  strategy.ts
  parameters/
    backtest.json
  backtest_trades.csv
```

An ML/Bayes/logit/stump strategy usually looks like this:

```text
strategy/my_new_bayes_strategy/
  strategy.ts
  machine_learning/
    selection.json
  backtest_trades.csv
```

The Python engine discovers metadata in this order:

1. `strategy/<folder>/machine_learning/selection.json`
2. `strategy/<folder>/bayes/selection.json`
3. `strategy/<folder>/parameters/backtest.json`

Only one of those should be the real source of truth for a strategy. Keep old or experimental metadata out of the folder unless the engine is supposed to read it.

## Example Strategy Registration

Most `strategy.ts` files are intentionally small:

```ts
import { createStrategyDefinition, runtimeDefaultsFromMetadata } from "@/lib/strategy-definition";
import { evaluateNySweepPlaybook } from "@/lib/strategy-runtime/ny-sweep-playbook";
import selection from "./machine_learning/selection.json";

export default createStrategyDefinition({
  id: "aud_usd_ny_sweep_bayes",
  label: "AUD/USD NY Sweep V4 Naive Bayes",
  folder: "aud_usd_ny_sweep_bayes",
  fileName: "strategy.ts",
  backtestFileName: "backtest_trades.csv",
  assetKey: "aud_usd",
  phase: "ny_sweep_playbook",
  liveEnabled: true,
  evaluator: evaluateNySweepPlaybook,
  defaults: runtimeDefaultsFromMetadata(selection)
});
```

Important fields:

- `id`: must match the strategy id used by the backtest engine.
- `folder`: must match the folder name under `strategy/`.
- `assetKey`: must exist in `config/assets.json`.
- `phase`: strategy family name used by stats, visuals, and runtime grouping.
- `liveEnabled`: set true only when the strategy evaluator supports live signal checks.
- `evaluator`: TypeScript function that evaluates the latest enriched bar.
- `defaults`: runtime parameters loaded from metadata.

## Strategy Signal Contract

Evaluators return a `StrategySignal` from `src/lib/strategy-definition.ts`.

Common fields:

- `side`: `long` or `short`
- `signalTime`: ISO time of the signal candle
- `entryPrice`: planned entry price
- `entryType`: `market` or `limit`
- `takeProfitPrice`: target price
- `stopLossPrice`: stop price
- `tpUnits`: target distance in asset units/ticks
- `slUnits`: stop distance in asset units/ticks
- `score` and `confidence`: optional quality values
- `notes`: optional short explanation for the signal

Use `roundToTick(...)` from `src/lib/strategy-runtime/helpers.ts` when calculating prices. Always respect the asset tick size.

## Available Runtime Candle Fields

Strategy evaluators receive enriched bars from `src/lib/indicators.ts`. Useful fields include:

- Moving averages: `ema9`, `ema12`, `ema21`, `ema30`, `ema34`, `ema50`, `ema200`
- Volatility: `atr14`, `atr100`, `bbWidthAtr`, `bbWidthPct200`
- Momentum: `rsi2`, `rsi14Centered`, `adx14`, `ret3Atr`, `ret6Atr`, `bodyAtr`
- VWAP: `sessionVwap`, `sessionStd`, `vwapZ`, `vwapSlopeAtr`
- Candle/session context: `closeLocation`, `nyDate`, `nyMinutes`, `nyWeekday`
- Trend/location helpers: `closeEma200Atr`, `bbZ20`, `priorHigh55`

Tell AI agents to use these existing fields before adding new indicator code.

## Metadata Keys the Engine Understands

The backtest engine reads a broad set of metadata keys. The most common ones are:

```json
{
  "strategyId": "my_strategy",
  "label": "My Strategy",
  "folder": "my_strategy",
  "assetKey": "nasdaq_100_futures",
  "phase": "reddit_orb_breakout",
  "variantId": "tf=15m|rr=2|max_bars=96",
  "source": "manual_research",
  "oneTradePerDay": true,
  "costUnits": 1,
  "tpUnits": 40,
  "slUnits": 20,
  "sizeMultiplier": 1,
  "selectionMethod": "human described, AI coded, fixed parameters",
  "trainingWindow": {
    "start": "asset_start",
    "end": "2021-12-31"
  },
  "forwardWindow": {
    "start": "2022-01-01",
    "end": "asset_latest"
  }
}
```

Policy fields supported by both metadata and runtime defaults:

- `stopLossPolicy.mode`: `signal_extreme` or `prior_day_extreme`
- `takeProfitPolicy.mode`: `risk_multiple`, `signal_extreme`, or `prior_day_extreme`
- `sizePolicy.mode`: `confidence`
- `dynamicStopLossPolicy.mode`: `trail_prior_bar` or `trail_hourly_pivot`
- `dynamicTakeProfitPolicy.mode`: `trail_prior_bar`, `risk_multiple`, or `trail_hourly_extreme`
- `entryMode`: `market` or `limit`
- `invertSignal`: true for opposite/inverted variants

Keep metadata honest. If a strategy was selected using a training split, write the split into the metadata. If it was manually chosen after looking at forward results, say that instead of pretending it was a clean holdout.

## Backtest Engine

Use the Python backtest engine for strategy validation. Do not ask an AI agent to create a separate backtester for normal strategy work.

Prepare derived timeframe data:

```powershell
python backtest-engine/runner.py prepare-data
```

Run one strategy:

```powershell
python backtest-engine/runner.py run-backtests --strategy my_strategy --timings
```

Run a smoke test without writing CSV files:

```powershell
python backtest-engine/runner.py run-backtests --strategy my_strategy --tail-bars 3000 --no-write --timings
```

Run every strategy:

```powershell
npm run backtest
```

List discovered strategies:

```powershell
python backtest-engine/runner.py list-backtests
```

Audit anti-cheat behavior:

```powershell
python backtest-engine/runner.py audit-anti-cheat --strategy my_strategy
```

Strict anti-cheat mode is the default. The engine slices visible data before each decision so the strategy cannot accidentally see future candles. `--fast-unsafe` exists for exploratory speed only. Do not use `--fast-unsafe` for final results.

Backtest output is written to:

```text
strategy/<strategy-id>/backtest_trades.csv
```

The dashboard reads columns such as:

- `strategy_id`, `asset_key`, `phase`, `variant_id`
- `side`, `signal_time`, `entry_time`, `exit_time`
- `entry_price`, `exit_price`
- `net_units`, `r_multiple`
- `tp_units`, `sl_units`, `cost_units`
- `exit_reason`, `bars_held`
- `source`, `tp_mode`, `sl_mode`, `size_mode`, `size_multiplier`

## Train/Test Split for Bayes and ML Strategies

This repo treats `2022-01-01` as the important forward-test boundary.

- Training window: `asset_start` through `2021-12-31`
- Forward window: `2022-01-01` through `asset_latest`
- Backtest constant: `BACKTEST_START_TS = 2022-01-01 UTC` in `backtest-engine/runner.py`
- ML rebuild script: `backtest-engine/rebuild_ml_holdout.py`

For Bayes/logit/stump strategies, use:

```powershell
python backtest-engine/rebuild_ml_holdout.py --strategy my_bayes_strategy --dry-run
python backtest-engine/rebuild_ml_holdout.py --strategy my_bayes_strategy
```

For the slowest but cleanest check, use:

```powershell
python backtest-engine/rebuild_ml_holdout.py --strategy my_bayes_strategy --strict
```

What this script does:

1. Searches/selects the lightweight model using only pre-2022 data.
2. Freezes the chosen candidate.
3. Regenerates post-2022 forward trades without refitting on forward data.
4. Writes `machine_learning/selection.json` with `trainingWindow`, `forwardWindow`, selected training metrics, selected forward metrics, and a verification summary.
5. Writes `backtest_trades.csv` with forward trades.

AI agent rule: never tune Bayes/logit/stump thresholds on 2022+ performance and then call the result a holdout. If the prompt asks for a Bayes strategy, tell the agent to use `rebuild_ml_holdout.py` and preserve the pre-2022/post-2022 split in metadata.

## Per-Trade Chart Visuals

The trade modal is not only a PnL view. It can show structure overlays for the selected trade.

Main files:

- `src/components/trades/trade-history.tsx`: trade table and modal shell
- `src/components/trades/trade-price-chart.tsx`: candlestick chart, replay controls, entry/target/stop overlays, structure visuals
- `src/app/api/trade-chart/route.ts`: API route that returns context candles and optional 1m replay bars

The chart supports these timeframes:

```text
1m, 5m, 15m, 30m, 45m, 1h, 4h, 1d
```

Structure visuals live in `trade-price-chart.tsx`. Existing helper families include:

- opening range visuals
- support/resistance retest visuals
- trendline break visuals
- moving average pullback/crossover visuals
- VWAP pullback visuals
- liquidity sweep visuals
- order block breakout visuals
- parabolic fade visuals
- range edge visuals
- impulse/momentum visuals

When adding visuals for a new strategy family:

1. Add a helper such as `addMyStrategyVisuals(...)` in `trade-price-chart.tsx`.
2. Use the existing visual types: boxes, lines, segments, paths, tags.
3. Match the new strategy in `strategyStructureVisuals(...)` by `phase` or by the strategy fingerprint.
4. Keep visuals derived from candles, entry, stop, target, and strategy metadata. Do not add invisible strategy state that the chart API cannot reproduce.
5. Test the modal and turn on the `Structure` toggle.

Good structure visuals answer: "Why did this strategy take this trade here?"

Examples of useful overlays:

- Opening range high/low and breakout retest zone
- Swept liquidity level and reclaim candle
- Prior day high/low used as target or stop
- VWAP touch, deviation band, and reclaim path
- Trendline anchor points and break candle
- Support/resistance zone and retest candle
- Impulse leg, pullback box, and continuation trigger

```text
Review your own changes for lookahead bias, unregistered strategy imports, wrong assetKey, missing metadata, and missing per-trade visuals. Then run the relevant checks again.
```

## Common Mistakes to Avoid

- Forgetting to import/register the strategy in `src/lib/strategy-loader.ts`.
- Creating a strategy folder whose `folder`, `id`, and directory name do not match.
- Using an `assetKey` that does not exist in `config/assets.json`.
- Hardcoding tick sizes or symbols inside strategy logic.
- Letting a strategy evaluator inspect future bars.
- Using `--fast-unsafe` for final results.
- Training Bayes/logit/stump settings on 2022+ data.
- Adding per-trade visuals in a new component instead of using `trade-price-chart.tsx`.
- Editing generated `backtest_trades.csv` by hand.
- Committing `.env.local`, provider keys, or account credentials.

## Final Mental Model

Describe the strategy in plain English. Ask the AI agent to implement it inside the existing strategy folder plus runtime evaluator pattern. Validate it with the Python backtest engine. If it is ML/Bayes, keep training before 2022 and forward testing after 2022. If the setup has structure that a trader should be able to inspect, add that structure to the per-trade chart modal.

That is the whole loop: describe, code, register, backtest, visualize, review, push.
